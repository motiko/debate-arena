# Web Venue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `apps/web`, the web Venue. Viewers browse the feed, read and watch Debates live, and Members sign in with GitHub, start Debates, cast Oxford Audience Votes and manage their account. Lighthouse and axe checks gate every pull request.

**Architecture:**
- **Pages:** Astro 7 renders every page on the server inside its own Cloudflare Worker. Svelte 5 islands carry the only JavaScript: voting, the live Turn stream, the start form, sign-in and the account actions.
- **One origin:** the web Worker's own entry forwards every `/api/*` request, WebSocket upgrades included, to the API Worker through a service binding. Web and API therefore share one origin, so session cookies and Better Auth's origin check need no cross-site setup.
- **Server-side API calls:** pages call the API through the same binding with the typed `@debate-arena/api-client`, forwarding the Viewer's cookie.

**Tech Stack:**
- Astro 7.4, `@astrojs/cloudflare` 14.4, `@astrojs/svelte` 9.1, Svelte 5.57.
- Wrangler 4.162 (service bindings, dev registry).
- TypeScript 6.0 in `apps/web` only, for `astro check` and `svelte-check`.
- Vitest 5 with jsdom and `@testing-library/svelte` 5.4 for unit and component tests.
- Playwright 1.65 + `@axe-core/playwright` 4.14 for end-to-end tests.
- `@lhci/cli` 0.16 (Lighthouse 13) for the performance checks.

**Spec:** `GLOSSARY.md`; `docs/adr/0002` (Venue-agnostic API; only the web counts votes), `0004` (Astro + Svelte, quality bar), `0005` (GDPR, AI labels, no consent banner), `0006` (agent-first tooling, offline dev with fake models); roadmap row 4 in `docs/superpowers/plans/2026-11-13-roadmap.md`.

## Global Constraints

- **Quality bar (ADR 0004):**
  - Every key page (home, Debate page, start-a-Debate page) scores Lighthouse Performance ≥ 0.9, SEO = 1 and Accessibility = 1, measured as a mobile device on simulated slow 4G.
  - axe finds no `wcag2a`, `wcag2aa`, `wcag21aa` or `wcag22aa` violations on any key page, including the live Debate page.
  - Either failure blocks merge (CI job `web`).
- **WCAG 2.2 AA:**
  - Everything works keyboard-only, with a visible focus ring.
  - New live Turns and vote confirmations are announced through `aria-live="polite"` regions.
  - Animation stops under `prefers-reduced-motion: reduce`.
  - Contrast is ≥ 4.5:1 in both light and dark schemes.
- **No cookies or scripts beyond the essentials (ADR 0005):** no third-party scripts, fonts or trackers. Use the system font stack. Better Auth's session cookie is the only cookie.
- **AI labels (ADR 0005):** every Turn, Verdict and AI Audience Result carries a visible "AI-generated" label.
- **Self-Judging disclosure:** whenever a Judge is the same model as a Debater, the Verdict carries a visible badge. AI Voters that share a Debater's model are disclosed the same way. The start form warns before submit when the chosen Judge is a Debater's model.
- **GLOSSARY words in all UI copy:**
  - Use Debate, Motion, Side (For/Against), Debater, Turn, Phase, Verdict, Panel, Judge, Audience Vote, Audience Result, Swing, AI Voter, AI Audience Result, Member and Quota.
  - Never use match, topic, Pro/Con, round, score, user or credits.
- **i18n-ready:**
  - All UI copy comes from `src/i18n/en.ts` through `t(key, params)`.
  - Islands get their strings as props or import `t`.
  - No locale routing yet.
- **Same origin:**
  - The browser only ever calls relative `/api/...` URLs.
  - The web Worker forwards `/api/*` untouched: method, URL, headers, body and upgrade.
- **Offline dev (ADR 0006):** `pnpm dev` runs web on `http://localhost:4321` and the API on `http://localhost:8787` with fake models, with no secrets needed. Sign-in during dev uses the `x-dev-member` header (`DEV_AUTH` true only in dev and tests).
- **Tooling:** oxlint only, no formatter. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Turn text:** render it as plain text, with paragraphs split on blank lines. Never use `{@html}` or Markdown.

## Review Focus

1. **Hostile text:**
   - A Motion or Turn containing `<script>`, HTML entities or a 300-character unbroken word must render as literal text.
   - The text must wrap without horizontal scroll at a 320 px viewport.
   - Owner: Task 5, test `renders Motion and Turn text literally`, plus an e2e test at 320 px.
2. **A live Debate that loses its socket or misses events:**
   - Turns produced between page render and socket open must still appear exactly once.
   - A dropped socket shows a "Reconnecting…" status and resumes.
   - Owner: Task 7, tests `merges a refetch with live Turns without duplicates` and `reconnects after the socket closes`.
3. **JavaScript disabled or slow to load:**
   - The feed, a finished Debate and its Verdict are fully readable from server HTML.
   - Islands enhance the page but never gate reading. A signed-out Viewer can read Turns.
   - Owner: Task 10, e2e test `debate page reads without JavaScript`.
4. **Unknown or broken input:**
   - `/debates/<unknown id>` returns the 404 page with HTTP 404, not a 500.
   - An API error while starting a Debate (400, 401, 429 Quota) shows the API's message in a `role="alert"` region and keeps the form values.
   - Owners: Task 5 (`unknown Debate id responds 404`) and Task 8 (`shows the API error and keeps the input`).
5. **Account deletion with an old login:**
   - Better Auth refuses deletion with code `SESSION_EXPIRED` when the session is over a day old.
   - The page must explain this and offer to sign in again, never fail silently.
   - Owner: Task 9, test `asks to sign in again when the session is too old to delete`.
